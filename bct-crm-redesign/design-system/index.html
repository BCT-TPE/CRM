BCT CRM V1

Tokens, components and rules for the CRM redesign. The blue-glass theme (v2) is the standard.

How to use

Load design-system/tokens.css before assets/crm.css on every page, then use var(--…) for every font size, colour, radius and shadow. If a value is missing, add a token here first. Never copy a raw value from a nearby rule.

FileWhat it holds

Type

Inter, eleven sizes and nothing in between. Body text is 14px. Sentence case everywhere. Proper nouns stay capitalised.

Colour

Blue family only. Red is reserved for overdue and needs attention. Forecast categories keep their colour on every page: Closed won is midnight, Commit is deep, Best case is cyan, Pipeline is blue-gray.

Radius & shadow

Cards and popovers are 16px. Controls on the canvas are pills. Every white object on the canvas uses the card shadow. Controls inside a card stay flat, because the card carries the shadow.

Spacing & layout

4px steps. Cards are 24px inside, the grid gap is 16px, and the page side padding is 40px. Text never sits closer than 24px to a card edge.

Components

Buttons and links

One primary button per view. Secondary buttons on a white card take a soft blue fill so they still read as buttons.

Filter row

One filter row per page. Every card, chart and table on the page responds to it. Selects are custom menus (crm.js), never native.

Confirm dialog

Save changes?

Your changes will be lost if you leave without saving.

CRM.confirm({ title, body, actions }). Short, general wording: no field lists. The destructive choice is red text on the left; the safe or main choice is the primary button. Esc and a click outside keep editing. CRM.guardLeave() asks before a page with unsaved input is left by a link, Cancel or the browser's back button.

Text field and date picker

Every <input type="date"> becomes the date picker (crm.js), never the browser's own. Close dates offer the fiscal quarter ends; other dates offer Tomorrow and Next week. Dates are written 18 Nov 2026 everywhere, or 18 Nov when the year is clear (CRM.date(d, year)).

Rules

Do

  • Use tokens for every font size, colour, radius and shadow.
  • Keep one filter row per page, and make every number on the page answer to it.
  • Show the records behind every number: a row or mark opens the list or the record.
  • Write labels in sentence case, and keep stage names lower case mid-sentence.
  • Let tables scroll sideways on small screens instead of hiding columns.
  • Open menus above everything, so cards and sticky bars never cut them off.
  • Write dates as 18 Nov 2026.
  • Ask before leaving a page with unsaved input.

Don't

  • Write px font sizes or raw hex colours in pages or shared CSS.
  • Use red for anything except overdue and needs attention.
  • Add a second tinted card, a dark accent card or decorative arrows.
  • Put shadows on controls inside a card.
  • Use native selects. Use the custom menu from crm.js.
  • Use a dashed underline for anything except a definition tooltip.
  • Use the browser's date picker. Use the one from crm.js.
  • Disable a create or save button to show that fields are missing.

Responsive

Designed at 1440. Every page also works down to a 390px phone.

WidthWhat changes
≤ 1360Header KPIs drop under the greeting. The filter row wraps.
≤ 1180Small cards sit in pairs, wide ones go full width. Funnel KPI tiles go 3 across.
≤ 1100The sidebar becomes the icon rail. Page padding is 24px. Tables scroll sideways with the first column pinned. On the record and new-initiative pages, the right rail moves under the form.
≤ 768The sidebar becomes a drawer behind a top bar. Every card is full width. The filter row stops sticking.
≤ 480Phone: 16px padding inside the page and cards, header KPIs 2 × 2, smaller page title and figures, forms in one column. The save bar shows the status above two full-width buttons.
